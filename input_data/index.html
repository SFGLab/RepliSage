    Input data¶

    What RepliSage reads, and in which format. Only the CTCF file and a region are required; everything else is optional. How the data are turned into model quantities is explained in Pre-processing and the replication model.

    Input Flag (config key) Required Used for
    CTCF sites --bedpe-file (BEDPE_PATH) yes loop anchors and CTCF barriers
    Region --region (CHROM, REGION_START, REGION_END) yes (or a whole chromosome) the modelled stretch of DNA
    Replication timing --rt-file (REPT_PATH) no S phase, forks, compartments
    Reference genome --motif-genome (MOTIF_GENOME) no CTCF orientation from DNA
    Hi-C map --hic (HIC_FILE) no validation of the model

    Region and beads¶

    The region is a chromosome and, optionally, a start and an end in base pairs, for example --region chr14:80835000-98674700. A bare chromosome (--region chr14) models the whole chromosome. The region is cut into N_BEADS equal beads (default: region length / 7 kb, at most 10,000); bead sizes outside 200 bp - 50 kb are an error.

    CTCF sites¶

    A tab-separated file; the format follows the extension (.gz is accepted). Only rows fully inside the region are used. CTCF orientation is the probability \(o\) that a site faces reverse: 0 = forward only, 1 = reverse only, negative = unknown.

    .bedpe: loops (one per line)

    Column Content
    1-3 Chromosome, start, end of the first anchor
    4-6 Chromosome, start, end of the second anchor
    7 Loop strength \(w\) (for example a ChIA-PET or HiChIP score); empty = 1, negative = 0
    8, 9 Optional: orientation \(o\) of each anchor

    .bed and .narrowPeak: ChIP-seq peaks (no loops, so loop figures and PREFERENTIAL_BINDING are off)

    Format Weight \(w\) Position Orientation (optional)
    .bed column 5 (score; 1 if missing) middle of the interval column 7 = \(o\), or the strand in column 6 (+ = forward, - = reverse)
    .narrowPeak column 7 (signalValue; the score in column 5 if all zero) summit (column 10), else the middle extra column 11 (or 6) with the probability of forward orientation

    Without any orientation the model still runs, treating every site as a barrier for both legs; give a reference genome to read it from the sequence.

    Replication timing¶

    Without timing there is no replication, no forks and one DNA chain. Give it with --rt-file:

    Format Content Notes
    .bigWig, .bw Bulk Repli-Seq signal (for example ENCODE) averaged in bins, log-transformed, Gaussian-smoothed
    .txt Tab-separated table, value in the third column one value per genomic window
    .parquet Single-cell timing matrix (columns starting with SC_) the shipped file is src/data/replication_timing_data.parquet
    builtin The shipped single-cell GM12878 data covers the chr14 test region
    none no replication loop extrusion only

    In a terminal, with no timing given, RepliSage asks what to do (ASK_RT = False switches the question off). In every case the signal becomes \(f_i \in [0, 1]\) along the beads: close to 1 replicates early, close to 0 late.

    Reference genome and CTCF motif finder¶

    Why. CTCF blocks a loop extruder only from one side, so the orientation of a site decides which LEF leg it attracts: a forward site attracts the left leg, a reverse site the right leg. Many inputs (ChIA-PET loops without motif columns, plain ChIP-seq peaks) carry no orientation. The motif finder fills it in from the DNA sequence. It is off by default and switched on by giving a genome: --motif-genome genome.fa (config: MOTIF_GENOME). Orientations already in your file are kept; only sites without one are scanned.

    How it searches. It is a standard position-weight-matrix scan, in four steps:

    1. The motif (a count matrix, the JASPAR CTCF MA0139.1 by default) becomes log-odds scores: for each position and base, \(\log_2 \big(P(\text{base} \mid \text{motif}) / \tfrac14\big)\), with a small pseudocount so unseen bases do not give \(-\infty\).
    2. Every window of the anchor or peak sequence is scored on both strands: the score \(s\) is the sum over positions (higher = closer to the consensus).
    3. A window is a hit if \(s\) exceeds the threshold that random DNA reaches with probability MOTIF_PVALUE (computed exactly, not by sampling).
    4. The site's orientation is the share of hit weight on the reverse strand, each hit weighted by \(2^{s}\) (its likelihood ratio): \(o = \sum_{\text{reverse}} 2^{s} / \sum_{\text{all}} 2^{s}\). A site with no hit stays unoriented.

    Options. Only --motif-genome has a flag; the rest are config keys (see Configuration).

    Key Default Meaning
    MOTIF_GENOME (--motif-genome) empty = off Reference genome: an uncompressed FASTA. An index .fai is created next to it if the folder is writable. Chromosomes with or without chr both work
    MOTIF_PFM built-in CTCF Your own motif: 4 rows of counts for A, C, G, T, equal length (JASPAR A [ ... ] lines are accepted)
    MOTIF_PVALUE 1e-5 Hit threshold: smaller = stricter, fewer hits
    MOTIF_PSEUDOCOUNT 0.8 Smoothing of the motif counts
    MOTIF_PAD 0 bp added on both sides of each site before scanning, for sites a little off the motif

    Hi-C map¶

    A .hic file (--hic) read with hic-straw (pip install "pyRepliSage[hic]"). The chromosome must be in the file. Bin size and normalisation are chosen automatically, with fallbacks (see Pre-processing); the region must fit in at most 6000 bins of the chosen size.

    What runs depends on the inputs¶

    You give What runs
    CTCF file and region loop extrusion, then 3D structures (MD) and the report
    + replication timing + replication, sister chromatids, A/B epigenetic states
    + reference genome + CTCF orientation from the motif
    + Hi-C map + validation against Hi-C

    Switch the 3D part off with --run-md false (config: SIMULATION_TYPE = none).
